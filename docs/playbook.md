# 銷售與經營手冊

怎麼賣、怎麼介紹、誰負責什麼，以及哪些事已經交給系統自己做。

## 三種角色

| 角色 | 是誰 | 用什麼 |
| --- | --- | --- |
| 平台方（你） | 經營「約好」這個服務 | 營運後台 `/admin` |
| 租戶（店家） | 美髮、美甲、教練等，付你月費 | 店家後台 `/dashboard` |
| 客人 | 店家的顧客，不付你錢、不用註冊 | 店家的預約頁 `/b/店名` |

這是多租戶的服務：所有店家共用同一套系統，資料互相隔離。你部署一次，就能服務所有店家。

## 一間店從開始到付費

1. 在首頁按「免費開一個預約頁」，填店名、選行業、取網址，約三分鐘。
2. 系統依行業先建好常見服務與營業時間，店家改成自己的價目。
3. 把預約連結貼到 IG、LINE，或印 QR Code 放櫃檯。
4. 客人開始自己約。店家收到通知信，每天看後台的預約本，做完按「完成」。
5. 電話或現場來的預約手動記進去，空檔會同步。
6. 升級點有兩個：想加第二位設計師，或每月 30 筆免費額度用完。到帳單頁刷卡，之後自動扣款。

客人那邊：打開連結 → 選服務 → 選人和時間 → 留姓名手機 → 畫面蓋上「約好了」。前一天收到提醒，可以自己改期或取消。

## 你負責什麼

| 你負責 | 你不負責 |
| --- | --- |
| 系統正常運作、資料不遺失 | 店家的服務品質和定價 |
| 向店家收月費、開發票 | 店家和客人之間的金錢（客人到店付現） |
| 店家的客服（帳號、付款、怎麼用） | 客人的客服（客人找店家） |
| 個資保管，外洩時通報 | 店家怎麼使用自己的顧客名單 |
| 處理違規店家 | 客人爽約造成的損失 |

客人的錢不經過你，所以你沒有代收代付的責任。

## 怎麼介紹

**一句話**：「客人自己在手機上選時間約好，你不用再回訊息喬時間。」先講這句，功能留到對方有興趣再說。

**五分鐘示範**（面對面或傳訊息都適用）

1. 拿他的手機打開示範店家的預約頁，讓他自己約一筆。先讓他以客人的角度體驗。
2. 再給他看後台，剛剛那筆已經出現在預約本上。
3. 問他：「你現在一天回幾則喬時間的訊息？」
4. 當場幫他開好帳號、建好他的三項服務，把連結傳給他。

也可以直接傳影片：`marketing/out/` 裡有 Reels 和完整使用流程。

## 常見疑慮

| 店家說 | 你回 |
| --- | --- |
| 我客人都用 LINE 約 | 連結就貼在 LINE 裡，客人一樣從 LINE 點進來，只是不用等你回 |
| 我怕客人不會用 | 不用下載、不用註冊，選三下就好，剛剛你自己試過了 |
| 要錢嗎 | 一個人的店免費用，沒有期限。請第二個人或預約變多再付，一個月 499 |
| 我已經在用別家 | 別家多半按人頭算，你們三個人一個月要多少？我們五個人以內都是 499 |
| 客人爽約怎麼辦 | 付費版會在前一天自動提醒客人；客人臨時不能來可以自己取消，時段馬上還給你 |
| 我的資料安全嗎 | 每間店的資料互相隔離，每天備份；你可以隨時匯出或整個刪除 |
| 我再想想 | 帳號我先幫你開好，連結在這，你今晚貼到 IG 試一週 |

最後一句最重要：不要等他決定，先讓他收到第一筆預約。收到第一筆預約的店家才會留下來。

## 前十間店

找認識的人，親自去設定，不要先投廣告。目的是聽他們哪裡卡住，而不是營收。每週問一次：

- 這週有幾筆是從預約頁進來的？
- 有沒有哪個客人說不會用？卡在哪一步？
- 你自己最常開後台的哪一頁？哪一頁從來沒開過？

## 已經交給系統的事

| 事情 | 系統怎麼做 |
| --- | --- |
| 開店、設定、升級、換方案、取消、刪除帳號 | 店家全部自己來 |
| 收款 | 每月或每年自動扣款；失敗時寄信、保留 3 天、到期自動降級 |
| 提醒升級 | 免費額度用到八成和額滿時，自動寄信給店家 |
| 教新店家上手 | 開店後第 1、3、7 天，還沒收到線上預約就自動寄信教下一步 |
| 回答常見問題 | 後台的「使用說明」；引導信也會帶到那裡 |
| 預約通知、前一天提醒、改期與取消通知 | 自動寄出 |
| 備份 | 每天一份，另有加密的異地備份 |
| 告訴你哪裡出事 | 寄信失敗、扣款失敗、訂閱卡住、備份沒成功時寄信給你；每週一寄一封生意概況 |

## 還是需要人的事

| 事情 | 頻率 | 說明 |
| --- | --- | --- |
| 賣給新店家 | 持續 | 早期只能靠人。週報會列出「開店三天還沒有預約」的店家，那是最值得主動聯繫的名單 |
| 回客服信 | 有人問才需要 | 店家直接回任何一封系統信，就會寄到 `SUPPORT_EMAIL` |
| 開發票 | 每筆收款 | 目前要在綠界後台手動開 |
| 退款與扣款爭議 | 偶爾 | 在綠界後台處理，需要人判斷 |
| 套件安全更新 | 每月一次 | `npm audit`、`npm update`，測試通過後部署 |
| 處理系統寄來的異常通知 | 有才需要 | 信裡會寫該做什麼 |

網站整個掛掉時，系統沒辦法自己寄信通知你，所以仍然需要一個外部監控（UptimeRobot 之類）打 `/api/health`。

## 推薦獎勵（不用寫程式）

介紹一間店付費，雙方各送一個月：在營運後台對兩間店各用一次「手動方案」，原因欄寫「推薦獎勵」，稽核紀錄會留著。
