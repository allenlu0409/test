# 資安與個資

## 已實作的防護

| 風險 | 做法 | 位置 |
| --- | --- | --- |
| 密碼外洩 | scrypt 加鹽雜湊；最短 8 碼 | `lib/password.ts` |
| 登入狀態被竊 | 隨機 256 位元 token，資料庫只存雜湊；Cookie 為 HttpOnly、SameSite=Lax、正式環境 Secure；改密碼或重設後登出所有裝置 | `lib/auth.ts` |
| 暴力猜密碼 | 以「IP＋帳號」限流；帳號不存在時也做一次雜湊比對，避免從回應時間判斷 Email 是否註冊 | `app/actions/auth.ts` |
| 跨店家存取資料 | 每個後台查詢與寫入都以登入者的 `business_id` 為條件；別家店的服務或人員 id 會被拒絕（有測試） | `app/dashboard/actions.ts` |
| SQL 注入 | 全部使用參數化查詢 | `lib/db.ts` |
| XSS | 輸出一律經 React 轉義；結構化資料另外轉義 `<`；有內容安全政策 | `next.config.ts` |
| CSRF | Server Actions 內建來源檢查；Cookie 為 SameSite=Lax | Next.js |
| 點擊劫持、MIME 嗅探 | `X-Frame-Options`、`frame-ancestors`、`nosniff`、HSTS | `next.config.ts` |
| 偽造金流通知 | 綠界 CheckMacValue 與 Stripe 簽章皆以定時比較驗證；另核對商店代號與金額等於方案價格；重送不重複入帳 | `lib/ecpay*.ts`、`lib/stripe.ts` |
| 重複預約 | 交易內重新檢查空檔 | `lib/booking.ts` |
| 灌單與爬蟲 | 三層限流、蜜罐欄位、免費版額度 | `proxy.ts`、`lib/ratelimit.ts` |
| 冒用電話竄改顧客資料 | 線上預約不能覆寫既有顧客的姓名與 Email | `lib/booking.ts` |
| CSV／行事曆注入 | 匯出時處理公式開頭字元與換行 | `lib/csv.ts`、`ics/route.ts` |
| 管理者提權 | 管理者名單在環境變數而非資料庫；必須是驗證過信箱的帳號；非管理者開 `/admin` 得到 404；管理操作留稽核紀錄 | `lib/admin.ts`、`lib/auth.ts` |
| 冒用他人信箱註冊 | 註冊後寄驗證信；信箱未驗證前不寄任何通知給該信箱，也不能進營運後台 | `app/actions/auth.ts`、`lib/notify.ts` |
| 店家被重複或錯誤扣款 | 要終止的定期定額先寫入佇列，每 10 分鐘重試到成功；沒有方案卻被扣款的訂閱會自動排入終止並留紀錄；續期通知核對金額 | `lib/billing.ts`、`lib/ecpay-events.ts` |
| 密碼外洩 | 兩步驟驗證（TOTP，相容各家驗證器 App），附一次性備用碼；營運後台的管理者強制開啟 | `lib/totp.ts`、`app/actions/auth.ts` |
| 容器被攻破後的影響範圍 | 伺服器以一般使用者執行，啟動時只用 root 修正資料磁碟權限後立刻降權 | `docker-entry.mjs` |
| 重設密碼連結外洩 | 一小時有效、一次性、資料庫只存雜湊；正式寄信時不保存信件內文 | `app/actions/auth.ts`、`lib/mail.ts` |
| 卡號外洩 | 卡號只在綠界／Stripe 的頁面輸入，本系統不經手也不儲存 | — |

程式碼經過兩輪獨立審查，未發現跨店家資料外洩或注入問題；兩輪共找到 15 個缺陷（含 5 個會造成重複預約、錯誤扣款或權限問題的嚴重缺陷），已全數修正並補上測試。

## 尚未做、你該知道的

- **限流存在單機記憶體**，重啟後歸零；多台主機時需換成 Redis。
- **兩步驟驗證的密鑰以明文存在資料庫**（驗證時需要原值）。資料庫外洩時應請所有使用者重設。
- **手機遺失且備用碼也不見**時，使用者無法自行復原。處理方式：確認身分後，直接在資料庫把該帳號的 `totp_enabled` 設為 0。
- **資料庫檔案未加密**。安全性取決於主機與磁碟的存取控制；備份檔下載到個人電腦後請放在加密磁碟。
- 未做過第三方滲透測試。

## 機密管理

- 金鑰只放在主機平台的機密設定（`fly secrets`）或主機上的 `.env`，不進版控。`.gitignore` 已排除 `.env*` 與資料庫檔。
- 金鑰外洩時：到對應服務（綠界、Resend、Stripe）重新產生，更新機密並重新部署。
- `CRON_SECRET` 用 `openssl rand -hex 24` 產生。

## 個人資料（台灣個資法）

**你的角色**：店家的帳號資料由你蒐集，你是蒐集者。預約客人的資料由各店家蒐集，你是受委託處理的一方。

**蒐集的資料**
- 店家：稱呼、Email、密碼雜湊、店家資訊。
- 預約客人：姓名、手機、Email（選填）、預約內容、店家寫的備註。
- 技術資料：限流用的 IP（只在記憶體中，不落地）、登入 Cookie。

**已支援的當事人權利**
- 查詢與更正：店家可在後台查看與修改；客人可從預約連結查看自己的預約。
- 刪除：店家可刪除單一顧客的個人資料（姓名、手機、Email、備註會被抹除，保留去識別化的預約紀錄供帳務使用）；店家可自行刪除帳號，所有資料立即連帶刪除。
- 可攜：專業版以上可匯出顧客與預約的 CSV。

**保存期限**：寄信紀錄 30 天、稽核紀錄一年、主機上的備份 7 天、異地備份 30 天。帳號資料保存到帳號刪除為止。刪除帳號後，備份中的資料最多再留 30 天。

**上線前要做**
- 設定 `OPERATOR_NAME` 與 `SUPPORT_EMAIL`，條款與隱私權政策會自動帶入。條文內容（`src/app/(legal)/`）是通用範本，最好請律師看過。
- 決定資料外洩時的通報流程：個資法要求查明後通知當事人。
